- 로컬 설정 권한: `0600`. 요청 타임아웃: 5초. 일반 실행 버튼·Ctrl+F5·CLI가 같은 설정을 자동으로 읽습니다.

기존 전송 코드의 경로·헤더·JSON·응답 검증이 계약과 호환되어 전송 코드나 외부 API 필드를 변경하지 않았습니다.
현재 송신기는 명시적인 순차 요청을 사용하며, 서버는 장치 시각만으로 보고를 거부하지 않습니다. 늦게 처리된 보고는 다음 최신 하트비트로 갱신됩니다.
서버의 `updated_count`는 변경된 좌석 수입니다. 관측 정보만 갱신되거나 동일한 하트비트면 0도 정상 응답입니다.

## 확인한 범위

1. `/health`와 방 조회가 실제 HTTPS `200`으로 응답했습니다. 서버에는 좌석 4개가 등록돼 있었습니다.
2. 기존 `StatusPublisher`와 실제 인증키로 관측 없는 `A-01=UNKNOWN`, `reason=STALE_OBSERVATION`, `confidence=null`을 보고했습니다. `last_observed_at`은 생략하고 분석 FPS는 0으로 보고했습니다.
3. 인증된 POST가 `200`으로 처리되고, 방 조회에서 `edge_online=true`, 버전 1, A-01의 새 사유를 확인했습니다.
4. 같은 작업자가 보낸 약 10초 뒤 하트비트도 `200`으로 처리됐습니다. 방의 버전과 좌석 관측 정보는 유지됐고, 보고하지 않은 나머지 좌석은 바뀌지 않았습니다.
5. 확인용 작업자를 종료한 뒤 서버가 30초 무응답을 감지해 `edge_online=false`, 전 좌석 `UNKNOWN/EDGE_OFFLINE`, 버전 2로 전환하는 것을 확인했습니다.

기존 전체 자동 테스트도 같은 환경에서 다시 실행해 136개가 통과했습니다.

이는 Pi에서 실행한 실제 HTTPS 송신·서버 조회 검사입니다. 카메라·YOLO는 사용하지 않았으며 실제 영상의 점유·짐·빈자리 판정이나 성능 검증을 뜻하지 않습니다.
인증 확인용 보고로 OCCUPIED/AWAY/EMPTY 같은 점유 상태를 만들어 보내지 않았습니다.

## 사용자 확인과 4단계 완료

2026-11-19 사용자가 백엔드에서 JSON을 정상 수신했고 장치 연결 상태도 정상이라고 확인했습니다.
위의 에이전트 실서버 검사·기존 전송 실패/복구 자동 테스트·사용자 수신 확인을 근거로 **4단계 백엔드 전송을 완료**로 기록합니다.
사용자 확인은 자동 테스트나 측정된 탐지 정확도·FPS 결과와 구분합니다. EMPTY 검증기·선택적 로컬 VLM·웹을 포함한 최종 시스템 평가와 현장 품질 계측은 5단계 및 별도 품질 검증 범위입니다.

## 평소 실행

기존처럼 `main.py`를 실행하고 **탐지 시작**을 누르면 이 서버로 상태 변경·10초 하트비트를 전송합니다.
탐지를 중지하면 하트비트도 중지됩니다. 서버의 `edge_online`은 프로그램이 실제로 보고하는 동안에만 true입니다.
확인 주소: [IT4-101 현재 상태](https://zeroframe-backend-p1wa.onrender.com/api/v1/rooms/IT4-101).

Render 무료 플랜의 휴면·재시작과 등록 좌석 변경은 기준 계약의 안내를 따릅니다. 첫 연결이 느린 동안에도 분석과 전송 재시도는 분리되어 있습니다.
