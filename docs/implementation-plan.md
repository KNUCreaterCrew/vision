# 구현 진행 기록

현재 기준: 4단계 전송부 및 Render 실서버 연결 확인 포함 · 2026-11-19 · ZeroFrame v1.1 Local Multimodal Edge · Vision 저장소.
단계별 최신 상태를 기록합니다. 설치·실행 절차는 [README](../README.md), 요구사항과 API 계약은 [명세서](../zeroframe_v1.1_local_multimodal.md)를 따릅니다.

## 현재 요약

- **1~2단계 구현, 3단계 기능 구현, 4단계 백엔드 전송 완료, 5단계 단독 VLM 진단 구현**입니다. 3단계 현장 정확도·성능 계측과 5단계 VLM 품질 개선·상태 연결·최종 시스템 검증은 남아 있습니다. 사용자가 실영상 검증은 보류하고 전송부 구현을 요청한 뒤, VLM 단독 검증을 승인했습니다.
- `main.py` 하나로 좌석 설정과 실시간 탐지를 실행합니다. 기존 좌표를 읽고, 처음이거나 방이 바뀌거나 저장 좌석이 상한을 초과하면 캘리브레이션부터 진행합니다.
- 사용자가 Windows 노트북에서 캘리브레이션 뒤 YOLO 실행 성공을 보고했습니다. 새 GUI의 전체 연속 조작과 실제 강의실 인식 품질은 별도 확인 대상입니다.
- 뒷모습·상반신 구도를 위해 **사람의 좌석 매핑**을 겹침 면적으로 보완했습니다. YOLO 모델 재학습이나 검출 정확도 검증을 수행한 것은 아닙니다.
- 최근 Pi ARM64 / Python 3.13.5에서 전체 자동 테스트 **175개 통과**. 카메라·모델 입력은 모의 객체이며 일부 전송 테스트는 실제 loopback HTTP를 사용합니다.
- Pi용 `.venv`와 apt OpenCV, CPU 전용 PyTorch·Torchvision, Ultralytics 8.3.253, 공식 `local/yolo11n.pt`를 준비했습니다. VS Code Ctrl+F5는 OS별 가상환경의 `main.py`를 실행합니다.
- C270의 실제 프레임 60개 수신, Pi 로컬 Tk 시작 창 생성, 검은 합성 프레임의 실제 YOLO 추론을 별도로 확인했습니다. 실제 좌석의 카메라→탐지→상태 전체 연결은 확인 대기입니다.
- 사용자 승인에 따라 개발 중 SSH 터널 화면 공유를 추가했습니다. Ctrl+F5의 Linux 개발 설정에서 WayVNC·noVNC를 함께 시작하며, 노트북 브라우저에서 기존 GUI를 조작합니다. 운영 모드·외부 API 계약은 바꾸지 않습니다.
- `zeroframe/transport.py`가 상태 변경·10초 하트비트·인증 POST·UTC 변환·최신 스냅샷·재시도를 구현합니다. 기존 `main.py`와 CLI가 같은 설정 파일을 읽습니다. 외부 API 필드는 변경하지 않았습니다.
- `mock_backend.py`와 `send_status_demo.py`로 카메라 없는 합성 상태 네 건의 실제 HTTP 수신을 확인했습니다. 이후 2026-11-19 배포된 Render 서버에서 실제 인증 POST·10초 하트비트·조회 반영·30초 오프라인 전환을 확인했습니다. 후자는 `A-01=UNKNOWN` 보고이며 카메라는 사용하지 않았습니다.
- 이후 사용자가 백엔드의 JSON 수신과 장치 연결 상태가 정상이라고 확인했습니다. 기존 자동 테스트와 에이전트 실서버 검사·사용자 보고를 근거로 4단계를 완료 처리하며, 이를 탐지 품질 계측 완료로 해석하지 않습니다.

## 전체 5단계

| 단계 | 구현한 내용 | 현재 상태 / 남은 확인 |
| :--- | :--- | :--- |
| 1. 상태 핵심 | 4상태, 시간 기반 전이, 입력 검증, 중복·오래된 관측 배제, 30초 만료, 합성 데모 | 구현·자동 테스트 완료. 선택형 빈자리 기준 비교는 실행기에 연결됨 |
| 2. 카메라·ROI | 로컬 카메라, RAM 화면 고정, 다각형 지정·검증, 좌표 JSON 저장, 취소·덮어쓰기 보호 | 구현·자동 테스트 및 사용자 노트북 실행 확인. 좌석별 현장 정합 보정 필요 |
| 3. YOLO·GUI | YOLO11n, ROI→상태 연결, 최신 프레임 유지, 지연 결과 폐기, 로컬 결과 화면, Tkinter 시작 창, 상반신 매핑 | 기능 구현·자동 테스트 완료, 노트북 YOLO 실행 성공 보고. GUI 연속 조작·상반신 검출률·Pi 성능 확인 대기 |
| 4. 백엔드 전송 | 상태 JSON·시각 변환, 인증 헤더, 변경 전송, 10초 하트비트, 장애 처리 | 완료. 실서버 인증 수신·하트비트·오프라인 처리 확인 및 사용자 JSON 수신·장치 연결 정상 보고 |
| 5. 선택적 VLM·통합 | 로컬 SmolVLM2, 단일 워커·제한 큐·만료·오래된 결과 폐기, 실제 서버 연동·최종 현장 평가 | 단독 진단·SSH 네 상태 비교·보수적 가시성 보류 구현. 선택형/256의 형식·속도 개선 확인, 현장 정답 검증·운영 연결 대기 |

현재 로컬 GUI는 Vision 확인 도구입니다. 백엔드의 30초 통신 단절 판정·WebSocket과 프론트엔드 좌석 지도는 별도 저장소의 책임입니다.
VLM을 도입하지 않더라도 통합·장애·프라이버시·성능 평가는 필요합니다.

## 실행 흐름과 구현 위치

1. `main.py`: 방·좌석·카메라·로컬 모델 입력, 기존 좌표 읽기, 실행·복귀·오류 안내.
2. `calibrate.py`: 필요 시 Space로 RAM 화면 고정 → 꼭짓점 지정 → 좌석마다 N → 다음 좌석을 계속 클릭 → 마지막에 S로 좌표 JSON 저장. 최대 좌석 수만 입력하면 1석부터 상한까지 자동 ID로 저장합니다.
3. `run_vision.py`: 카메라 최신 프레임 → YOLO → ROI 매핑 → 좌석별 상태, 탐지 상자·FPS·지연 표시.
4. `zeroframe/camera.py`: Windows DirectShow / Linux USB V4L2, 최신 프레임 하나 유지, 오류·종료 시 해제.
5. `zeroframe/detection.py`, `roi.py`, `state.py`: 탐지·좌표 계산·시간 기반 확정과 만료.
6. `zeroframe/transport.py`: 설정이 있을 때만 별도 작업자로 상태 메타데이터 전송. 카메라·추론 버퍼는 전달하지 않습니다.

카메라 작업 중 시작 창은 숨겨집니다. Q/Esc/카메라 창 닫기 또는 오류 시 시작 창으로 돌아옵니다.
모델 로딩에는 시간이 걸릴 수 있습니다. 기존 좌표 교체는 확인 후 실제 S 저장 시 적용하며, 취소하면 파일을 보존합니다.
좌석 일괄 생성, 런타임 모델 다운로드, 카메라 자동 재연결은 구현하지 않았습니다.

## 현재 판정·매핑 기준

| 항목 | 구현 기본값 |
| :--- | :--- |
| 탐지 대상 | person(0), backpack(24), handbag(26), bottle(39), laptop(63), cell phone(67), book(73) |
| 신뢰도 | person ≥0.50, 소지품 ≥0.35. 검출 하한 0.25 이상인 불확실한 탐지는 관련 좌석 보류 |
| 사람 ROI 연결 | 교차 면적 / min(좌석 다각형 면적, 보이는 사람 상자 면적) ≥0.50, 면적이 겹치는 좌석이 정확히 하나 |
| 여러 좌석·약한 겹침 | 관련 좌석의 새 확정과 최신성 갱신 보류. 물품만으로 AWAY를 새로 확정하지 않음 |
| 물품 ROI 연결 | 상자의 하단 중심점 포함 여부. 경계·다중 후보 보류 |
| 상태 전이 | 기본 주기에서 두 번 연속 사람→OCCUPIED, 두 번 연속 짐만→AWAY. 빠른 검사에서도 최소 지속 시간은 각각 2초, 3초(점유에서 짐만 남을 때 4초) |
| 최신성 | 관측 간격이 max(2초, 주기 × 1.5)를 초과하면 후보 초기화, 캡처 읽기부터 완료까지 2초 초과 결과 폐기, 마지막 유효 판정 30초 후 UNKNOWN |
| EMPTY | 지속적인 부재 5초와 동일 관측의 명시적 검증 필요. 확인된 빈자리 기준과 같은 프레임의 좌석 영상이 연속 3회 일치해야 EMPTY. 약한 그림자·반사 보정, 애매한 관측은 기존 EMPTY의 시각을 갱신하지 않고 30초 만료. 희미한 물품·조명 변화의 현장 검증 대기 |
| 분석 속도 | 시작 직후 검사, 이후 10초마다 최신 프레임 검사(0.1 FPS). CLI에서 0.1~3 FPS 설정 가능 |

상반신·뒷모습용 ROI에는 **그 좌석에 앉은 사람의 머리·어깨·등이 화면에 보일 공간**과 책상·의자를 포함합니다.
발이나 하반신이 보일 필요는 없습니다. 화면에서 잘린 사람 상자도 매핑할 수 있지만, YOLO가 먼저 person 상자를 만들어야 합니다.
경계에 닿기만 하고 교차 면적이 0이면 중복 후보가 아닙니다. 조금이라도 다른 좌석과 면적이 겹치면 보류하므로 실제 배치에서 보정해야 합니다.
기존 좌표 JSON 형식은 유지하며, 해상도·카메라 위치 변경 시 다시 캘리브레이션합니다.

## 운영 환경·프라이버시 범위

Windows 개발을 유지하며 **Raspberry Pi 5 8GB / 64비트 Raspberry Pi OS / USB 웹캠** 운영을 우선합니다.
Pi는 apt OpenCV와 `--system-site-packages` venv, GUI는 추가 `python3-tk`와 로컬 데스크톱을 사용합니다.
화면 없는 운영은 기존 CLI를 사용합니다. CSI 카메라는 Picamera2 캡처 경로가 별도로 필요해 현재 미지원입니다.
NCNN/ONNX 파일 로더는 있지만 ARM64 설치·모델 변환·추론·성능 비교는 아직 확인하지 않았습니다.
`.pt` 경로는 현재 Pi에서 패키지 import와 합성 입력 추론을 확인했으며 NCNN/ONNX와 실영상 비교는 남아 있습니다.
VS Code는 프로젝트 `.venv`를 직접 지정하며 Windows 경로를 Pi에서 사용하지 않습니다.
`main.py`는 `DISPLAY`가 없을 때 같은 사용자 소유 로컬 X 소켓이 하나인 경우에만 선택합니다. 기존 화면 설정은 유지합니다.

**개발 예외(2026-11-17 사용자 승인):** 개발·캘리브레이션 중에는 SSH 암호화 터널을 통해 신뢰하는 노트북으로 화면과 입력을 공유할 수 있습니다.
`zeroframe/dev_remote.py`는 WayVNC를 사용자 전용 Unix 소켓에, noVNC 프록시를 `127.0.0.1:6080`에만 엽니다.
Linux `main.py`는 `SSH_CONNECTION`을 직접 감지하며, VS Code Linux 개발 설정의 `ZEROFRAME_DEV_REMOTE=1` 또는 명시적 `--dev-remote`로도 활성화합니다. `--local`은 자동 감지보다 우선해 공유를 끕니다. 정상 종료·SIGTERM 시 서버와 임시 클라이언트 파일을 정리하며, `setpriv --pdeathsig TERM`으로 부모 종료 시 서버도 종료하게 합니다.
일반 실행 버튼은 `launch.json`의 환경 변수를 전달하지 않아 처음에는 GUI만 열리고 6080이 닫혀 있었습니다. 해당 프로세스의 SSH 환경과 연결 거부를 확인한 뒤 자동 감지를 보완했고, 인자 없는 실제 `main.py` 실행에서 HTTP·클라이언트 JS 200 응답을 확인했습니다.
실제 원격 입력 뒤의 연속 재시작과 부모 프로세스 강제 종료 후 포트 닫힘도 확인했습니다.
영구 서비스는 켜지 않습니다. 임시 디렉터리에는 정적 웹 클라이언트 경로·HTML만 두며 이미지·녹화 저장과 외부 이미지 API 사용은 계속 금지합니다.
운영·시연 배포는 이 모드를 사용하지 않고 비영상 상태 JSON만 전송합니다. 스왑·브라우저 캐시까지 검증한 것은 아닙니다.

이미지는 RAM에서만 처리하며 이미지·crop·라벨 저장을 끄고 추론 후 라이브러리의 원본 참조를 해제합니다.
모델은 신뢰하는 로컬 파일만 로드하며 Ultralytics 8.3.253을 고정합니다. 자동 설치·온라인 확인·통계/HUB 동기화를 비활성화합니다.
OS 스왑·페이지 파일·크래시 덤프·드라이버 버퍼와 실제 네트워크 무전송은 별도 검증 대상입니다.
소프트웨어 읽기 시각은 센서 노출 시각이 아니며, 드라이버 정지 시 프로세스를 완전히 종료해야 할 수 있습니다.

## 4단계 전송 설정과 운영 범위

설정이 없으면 전송을 끕니다. Git 제외된 루트 `transport_config.json`에 `backend_url`, `api_key`, 선택적 `timeout_seconds`를 두거나 `ZEROFRAME_BACKEND_URL`, `EDGE_NODE_SECRET_KEY`로 덮어씁니다.
기존 GUI/CLI가 공통으로 읽으며 CLI의 `--transport-config`로 경로를 지정할 수도 있습니다. HTTPS 인증서 검증을 사용하며 HTTP는 loopback만 허용합니다.
API 계약은 기존 5.1 그대로입니다. 보고 시각과 관측 시각을 분리하고 `confidence`는 항상 null, 현재 확정 점유·짐의 출처는 YOLO, UNKNOWN은 FALLBACK으로 보고합니다. 빈자리 기준 검증을 통과한 EMPTY는 선택 필드 decision_source 없이 전송합니다.
전송 작업자는 단일 요청과 최신 메타데이터 스냅샷 하나만 유지합니다. 오래된 실패 보고를 재생하지 않고 1/2/4/8/10초 지수 지연으로 최신 상태를 재시도합니다.
하트비트는 정상 상태에서 10초 주기이며 관측 시각을 새로 만들지 않습니다. 추론이 멈춰도 30초 만료를 전송 시 반영하고 누적 분석 FPS는 경과 시간에 따라 낮아집니다.
종료 시 작업자를 중지하고 메타데이터 버퍼를 버립니다. 기존 `main.py` 호출 방식은 유지합니다. 현재 Pi에는 Render 주소·비밀키·5초 타임아웃을 Git 제외된 권한 0600 설정 파일에 저장했습니다.
배포 서버와의 기준 계약은 [docs/INTERFACES.md](https://github.com/KNUCreaterCrew/docs/blob/main/INTERFACES.md)입니다. 서버는 장치 시각만으로 보고를 거부하지 않으며 순차 보고와 다음 최신 하트비트로 갱신합니다. 실제 30초 오프라인 전환까지 확인했고, WebSocket/프론트엔드 및 카메라 동시 운영은 별도 검증 대상입니다.
이미지·crop·배열 및 알려지지 않은 JSON 필드는 HTTP 요청 전에 거부합니다. 키·응답 본문을 로그에 출력하지 않습니다. `saved_frames_count=0`과 화이트리스트 검사만으로 전체 장비의 프라이버시를 입증한 것은 아닙니다.
