# 구현 진행 기록

현재 코드 기준: `4cdfe05` · ZeroFrame v1.1 Local Multimodal Edge · Vision 저장소.
단계별 최신 상태를 기록합니다. 설치·실행 절차는 [README](../README.md), 요구사항과 API 계약은 [명세서](../zeroframe_v1.1_local_multimodal.md)를 따릅니다.

## 현재 요약

- **1~2단계 구현, 3단계 기능 구현·현장 검증 중**입니다. 4단계 서버 전송과 5단계 선택적 VLM·최종 통합은 미구현입니다.
- `main.py` 하나로 좌석 설정과 실시간 탐지를 실행합니다. 기존 좌표를 읽고, 처음이거나 방·좌석 목록이 바뀌면 캘리브레이션부터 진행합니다.
- 사용자가 Windows 노트북에서 캘리브레이션 뒤 YOLO 실행 성공을 보고했습니다. 새 GUI의 전체 연속 조작과 실제 강의실 인식 품질은 별도 확인 대상입니다.
- 뒷모습·상반신 구도를 위해 **사람의 좌석 매핑**을 겹침 면적으로 보완했습니다. YOLO 모델 재학습이나 검출 정확도 검증을 수행한 것은 아닙니다.
- 최근 전체 자동 테스트 **96개 통과**. 이번 문서 갱신에서도 테스트 파일별 개수와 코드의 설정값을 대조했습니다.

## 전체 5단계

| 단계 | 구현한 내용 | 현재 상태 / 남은 확인 |
| :--- | :--- | :--- |
| 1. 상태 핵심 | 4상태, 시간 기반 전이, 입력 검증, 중복·오래된 관측 배제, 30초 만료, 합성 데모 | 구현·자동 테스트 완료. 실제 EMPTY 검증기는 없음 |
| 2. 카메라·ROI | 로컬 카메라, RAM 화면 고정, 다각형 지정·검증, 좌표 JSON 저장, 취소·덮어쓰기 보호 | 구현·자동 테스트 및 사용자 노트북 실행 확인. 좌석별 현장 정합 보정 필요 |
| 3. YOLO·GUI | YOLO11n, ROI→상태 연결, 최신 프레임 유지, 지연 결과 폐기, 로컬 결과 화면, Tkinter 시작 창, 상반신 매핑 | 기능 구현·자동 테스트 완료, 노트북 YOLO 실행 성공 보고. GUI 연속 조작·상반신 검출률·Pi 성능 확인 대기 |
| 4. 백엔드 전송 | 상태 JSON·시각 변환, 인증 헤더, 변경 전송, 10초 하트비트, 장애 처리 | 미구현. 수신 계약 및 재연결·통신 단절 검증 필요 |
| 5. 선택적 VLM·통합 | 로컬 SmolVLM2, 단일 워커·제한 큐·만료·오래된 결과 폐기, 실제 서버 연동·최종 현장 평가 | 미구현. VLM 활성화는 성능·정확도 검증 후 결정 |

현재 로컬 GUI는 Vision 확인 도구입니다. 백엔드의 30초 통신 단절 판정·WebSocket과 프론트엔드 좌석 지도는 별도 저장소의 책임입니다.
VLM을 도입하지 않더라도 통합·장애·프라이버시·성능 평가는 필요합니다.

## 실행 흐름과 구현 위치

1. `main.py`: 방·좌석·카메라·로컬 모델 입력, 기존 좌표 읽기, 실행·복귀·오류 안내.
2. `calibrate.py`: 필요 시 Space로 RAM 화면 고정 → 꼭짓점 지정 → 좌석마다 N → 마지막에 S로 JSON 저장.
3. `run_vision.py`: 카메라 최신 프레임 → YOLO → ROI 매핑 → 좌석별 상태, 탐지 상자·FPS·지연 표시.
4. `zeroframe/camera.py`: Windows DirectShow / Linux USB V4L2, 최신 프레임 하나 유지, 오류·종료 시 해제.
5. `zeroframe/detection.py`, `roi.py`, `state.py`: 탐지·좌표 계산·시간 기반 확정과 만료.

카메라 작업 중 시작 창은 숨겨집니다. Q/Esc/카메라 창 닫기 또는 오류 시 시작 창으로 돌아옵니다.
모델 로딩에는 시간이 걸릴 수 있습니다. 기존 좌표 교체는 확인 후 실제 S 저장 시 적용하며, 취소하면 파일을 보존합니다.
좌석 일괄 생성, 런타임 모델 다운로드, 카메라 자동 재연결은 구현하지 않았습니다.

## 현재 판정·매핑 기준

| 항목 | 구현 기본값 |
| :--- | :--- |
| 탐지 대상 | person(0), backpack(24), handbag(26), laptop(63), book(73) |
| 신뢰도 | person ≥0.50, 소지품 ≥0.45; 검출 하한 0.25 이상인 불확실한 탐지는 관련 좌석 보류 |
| 사람 ROI 연결 | 실제 다각형과 보이는 상자의 교차 면적 / 상자 면적 ≥0.50, 면적이 겹치는 좌석이 정확히 하나 |
| 여러 좌석·약한 겹침 | 관련 좌석의 새 확정과 최신성 갱신 보류. 물품만으로 AWAY를 새로 확정하지 않음 |
| 물품 ROI 연결 | 상자의 하단 중심점 포함 여부. 경계·다중 후보 보류 |
| 상태 전이 | 사람 2초→OCCUPIED, 짐만 3초→AWAY, OCCUPIED에서 짐만 4초→AWAY |
| 최신성 | 관측 간격 2초 초과 시 후보 초기화, 캡처 읽기부터 완료까지 2초 초과 결과 폐기, 마지막 유효 판정 30초 후 UNKNOWN |
| EMPTY | 지속적인 부재 5초와 동일 관측의 명시적 검증 필요. 실제 실행기는 검증기를 연결하지 않아 EMPTY를 생성하지 않음 |
| 분석 속도 | 목표 1~3 FPS, 기본 2. 실제 처리량 보장 아님 |

상반신·뒷모습용 ROI에는 **그 좌석에 앉은 사람의 머리·어깨·등이 화면에 보일 공간**과 책상·의자를 포함합니다.
발이나 하반신이 보일 필요는 없습니다. 화면에서 잘린 사람 상자도 매핑할 수 있지만, YOLO가 먼저 person 상자를 만들어야 합니다.
경계에 닿기만 하고 교차 면적이 0이면 중복 후보가 아닙니다. 조금이라도 다른 좌석과 면적이 겹치면 보류하므로 실제 배치에서 보정해야 합니다.
기존 좌표 JSON 형식은 유지하며, 해상도·카메라 위치 변경 시 다시 캘리브레이션합니다.

## 운영 환경·프라이버시 범위

Windows 개발을 유지하며 **Raspberry Pi 5 8GB / 64비트 Raspberry Pi OS / USB 웹캠** 운영을 우선합니다.
Pi는 apt OpenCV와 `--system-site-packages` venv, GUI는 추가 `python3-tk`와 로컬 데스크톱을 사용합니다.
화면 없는 운영은 기존 CLI를 사용합니다. CSI 카메라는 Picamera2 캡처 경로가 별도로 필요해 현재 미지원입니다.
NCNN/ONNX 파일 로더는 있지만 ARM64 설치·모델 변환·추론·성능 비교는 아직 확인하지 않았습니다.

이미지는 RAM에서만 처리하며 이미지·crop·라벨 저장을 끄고 추론 후 라이브러리의 원본 참조를 해제합니다.
모델은 신뢰하는 로컬 파일만 로드하며 Ultralytics 8.3.253을 고정합니다. 자동 설치·온라인 확인·통계/HUB 동기화를 비활성화합니다.
OS 스왑·페이지 파일·크래시 덤프·드라이버 버퍼와 실제 네트워크 무전송은 별도 검증 대상입니다.
소프트웨어 읽기 시각은 센서 노출 시각이 아니며, 드라이버 정지 시 프로세스를 완전히 종료해야 할 수 있습니다.
