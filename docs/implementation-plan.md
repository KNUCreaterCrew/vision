# 구현 진행 기록

기준: v1.1 Local Multimodal Edge / 현재 저장소 `KNUCreaterCrew/vision`.
초기 개발은 노트북과 내장 카메라로 진행하고, Raspberry Pi 5 검증은 별도로 수행합니다.
Windows 개발을 유지하며 Linux 운영을 우선합니다. 현재 Linux 카메라 경로는 USB 웹캠 기준이고 CSI는 별도 작업입니다.

## 전체 5단계

| 단계 | 범위 | 상태 |
| :--- | :--- | :--- |
| 1 | 4상태 모델, 시간 설정 검증, 상태 머신, 가짜 관측 데모·테스트 | 완료 |
| 2 | 노트북 내장 카메라 RAM 캡처, `calibrate.py`, ROI 저장·검증·매핑 | 구현·자동 테스트 완료 / 사용자 실행 확인 |
| 3 | YOLO11n 연결, 실제 카메라 판정, 로컬 GUI, 추론 경로 성능 검증 | 사용자 노트북 실행 확인 / GUI 연속 조작・현장 품질・Pi 성능 미검증 |
| 4 | 상태 JSON, 인증, 변경 전송·10초 하트비트, 통신 실패 처리 | 예정 |
| 5 | 선택적 로컬 VLM·단일 워커·제한 큐·만료·오래된 결과 폐기, 실제 백엔드 연동, 현장 보정과 최종 검증 | 예정 |

백엔드의 30초 통신 단절 처리와 프론트엔드는 별도 저장소의 책임입니다.
모델·카메라 등 외부 라이브러리는 해당 단계에서 공식 문서와 설치 환경을 확인합니다.
5단계에서 VLM 활성화는 선택이지만 통합·장애·품질·프라이버시·성능 검증은 필수입니다.
사용자 실행 안내와 단계별 완료 기준은 README를 기준으로 확인합니다.

## 1단계 결과

- 추가 패키지 없이 Python 표준 라이브러리만 사용합니다.
- 초기 상태 `UNKNOWN`, 사람 2초, 짐 3초, 점유→짐 4초를 적용했습니다.
- 빈자리 최초 확정도 지속적인 부재 5초와 현재 관측의 검증 신호를 요구합니다.
- 관측 간격 2초 초과·가림·모순된 판정은 후보의 연속 시간을 초기화합니다.
- 불확실한 관측은 마지막 확정 판정 시각을 갱신하지 않으며, 30초 후 `UNKNOWN`입니다.
- 설정·관측 값 검증, 중복·오래된 관측 무시, 시간 역행 거부를 구현했습니다.
- `status_since`와 마지막 유효 판정 시각을 분리했습니다. 내부 시간은 monotonic 초입니다.
- 외부 API 계약은 변경하지 않았습니다. 선택한 개발 기본값은 명세 4.2.1에 기록했습니다.

검증 환경: Windows 노트북, `python` 명령의 Python 3.14.5.

```powershell
python -m unittest discover -s tests -v
python -m zeroframe
```

상태 머신 테스트 25개 통과. 데모에서 4상태 전환과 30초 만료를 확인했습니다.
Python 3.10에서의 실행은 별도로 확인하지 않았습니다.

## 2단계 결과

- `calibrate.py`: 로컬 카메라 미리보기 → Space로 RAM 화면 고정 → 좌석별 꼭짓점 지정 → 좌표 JSON 저장.
- 카메라는 고정 화면을 선택하면 해제합니다. 취소·오류에서도 카메라/창 자원을 해제합니다.
- `zeroframe/roi.py`: ID·해상도·좌표·다각형 검증, JSON 저장·불러오기, 객체 하단 중심점 매핑.
- 경계와 겹침에서는 모든 후보를 반환합니다. 매핑 결과를 아직 상태 머신에 자동 연결하지 않습니다.
- 명시적 `--overwrite` 없이 기존 파일을 변경하지 않습니다. 덮어쓰기는 완성된 임시 JSON으로 교체합니다.
- `requirements.txt`에 GUI용 `opencv-python==4.13.0.92`를 추가했습니다. 사용자 환경에서는 도구 실행을 확인했으며, 에이전트 환경의 패키지 실행 검증은 완료하지 못했습니다.
- 기존 상태 머신 25개 + ROI/카메라/도구 제어 테스트 27개, **총 52개 통과**.
- `python calibrate.py --help`, 기존 `python -m zeroframe` 데모도 확인했습니다.
- 사용자 카메라 실행 로그에서 캘리브레이션 단계 진입을 확인했습니다. 좌석 두 개의 개별 확정이 혼동되어, 현재 좌석·점 수·완료 수와 다음 동작 안내를 추가했습니다. 실제 좌표 저장 성공은 아직 확인하지 않았습니다.

가짜 카메라·화면 이벤트로 저장, 취소, 다중 좌석, 되돌리기, 창 오류를 검증했습니다.
카메라 화면 진입은 사용자 로그로 확인했으며, 실제 좌표 저장과 개선한 UI 조작은 확인 대기입니다.
에이전트 실행 환경의 Python은 MSYS2 3.14.5이고 OpenCV가 없습니다. `pip install --dry-run`은 관리 환경 제한으로 실패했고,
등록된 Windows Store Python 3.13으로 가상환경을 만들려는 실행도 실패했습니다.
일반 Windows CPython 가상환경 설치·실행 방법은 README에 기록했습니다.

## Windows / Raspberry Pi OS Linux 호환성 점검

- Windows는 DirectShow, Linux USB 웹캠은 V4L2로 카메라 입력을 선택합니다.
- 상태 머신·ROI·JSON 코드는 OS 공통이며, Windows/Linux 플랫폼 분기를 모의 테스트합니다.
- Linux 캘리브레이션은 로컬 데스크톱을 요구합니다. 화면 없는 환경은 OpenCV 창을 열기 전에 안내 오류로 종료합니다.
- Pi OS는 apt `python3-opencv`와 `--system-site-packages` 가상환경을 사용합니다. pip OpenCV 요구사항은 Windows에만 적용합니다.
- 자동 테스트는 **총 55개 통과**했으며, Linux 플랫폼·화면 없는 환경으로 시뮬레이션한 전체 55개도 통과했습니다.
- 네이티브 Linux·ARM64·실제 Pi/웹캠/GUI 실행 검증은 수행하지 않았습니다. CSI 모듈은 Picamera2 경로를 별도로 구현해야 합니다.
- 설치 방법과 지원 범위를 README, Linux 우선 원칙을 AGENTS.md에 반영했습니다.

## 3단계 결과

- `zeroframe/detection.py`: 로컬 Ultralytics 8.3.253 어댑터와 COCO 클래스 검증, 사람 0.50·소지품 0.45 임계값.
- 기존 ROI 하단 중심점 매핑과 좌석별 상태 머신을 연결합니다. 낮은 신뢰도·겹친 ROI는 관련 좌석의 확정을 보류합니다.
- `run_vision.py`: CPU 추론, 목표 1~3 FPS(기본 2), 상태·평균 분석 FPS·predict 지연 출력, 선택적 로컬 미리보기.
- 카메라는 별도 스레드에서 연속으로 읽으며 최신 프레임 하나만 유지합니다. 읽기 시각과 결과 완료 시각을 분리하고, 2초 초과 지연 결과를 버립니다.
- `empty_verified`는 실제 YOLO 관측에서 항상 False입니다. 미탐지는 기존 판정을 갱신하지 않으며 30초 후 UNKNOWN입니다.
- 실행 중 모델 다운로드·패키지 자동 설치를 막고 통계/HUB 동기화를 비활성화합니다. 이미지·crop·라벨 저장은 끕니다.
- 고정 버전의 predictor가 유지하던 `batch/results/dataset/plotted_img` 참조를 매 추론 후 해제합니다. 카메라 오류는 정리 후 종료하며 재연결은 구현하지 않습니다.
- Windows 선택 의존성 `requirements-yolo.txt`, Pi의 apt OpenCV를 유지하는 분리 설치, 로컬 모델 준비·실행·문제 해결을 README에 기록했습니다.
- 기존 55개 + 캡처·YOLO 어댑터·매핑·좌석 추적·실행기 22개, **총 77개 자동 테스트 통과**. 실제 YOLO 대신 모의 출력과 RAM 프레임 대역으로 검증했습니다.
- Linux 플랫폼·화면 없는 환경으로 시뮬레이션한 전체 77개도 통과했습니다. 네이티브 Linux/ARM64 실행 결과는 아닙니다.
- 기존 상태 데모와 새 실행기의 `--help`도 통과했습니다. 에이전트의 MSYS2 Python에는 NumPy/PyTorch/Ultralytics가 없고, 기존 Windows Store 기반 `.venv`는 실행 권한 문제로 구동하지 못했습니다. 실제 가중치·추론은 아직 실행하지 않았습니다.
- 공식 YOLO11n 가중치 준비도 시도했으나 도구 환경의 네트워크 연결이 실패하여 다운로드되지 않았습니다. 사용자 PowerShell에서 README의 다운로드 명령이 필요합니다.

소프트웨어 캡처 시각은 센서의 노출 시각이 아닙니다. 드라이버 내부 버퍼 지연, 실제 가림·보행자·미탐지,
ARM64 설치·NCNN/ONNX 추론·FPS, 스왑/드라이버/실제 네트워크 관찰은 현장 검증 대상입니다.
카메라 드라이버가 읽기에서 멈추면 종료 대기 2초 후 오류를 내며, 프로세스를 완전히 종료해야 할 수 있습니다.

## 단일 GUI 실행 추가

- 사용자가 캘리브레이션 뒤 노트북 YOLO 실행 성공을 보고했습니다. 정확도·속도 계측이나 Pi 검증을 의미하지는 않습니다.
- `main.py`를 실행하면 Tkinter 시작 창에서 방·좌석·카메라·모델 경로를 지정합니다. 기존 좌표가 있으면 자동으로 읽습니다.
- '탐지 시작'은 좌표가 없거나 방/좌석 목록이 바뀐 경우 캘리브레이션 후 탐지를 이어갑니다. 기존 설정이 맞으면 즉시 탐지합니다.
- '좌석 설정 / 다시 설정'은 캘리브레이션만 실행합니다. 기존 파일 교체 전 확인하며 취소하면 파일을 보존합니다.
- 시작 창은 OpenCV 작업 동안 숨기고 Q/Esc/창 닫기·오류 시 복원합니다. 결과는 기존 로컬 미리보기의 상태·탐지 상자·FPS로 표시합니다.
- 추가 pip 의존성 없이 기존 `calibrate()`와 `run()`을 재사용했습니다. 영상 전달용 IPC·웹 서버·GUI용 복제 추론 루프를 만들지 않았습니다.
- 첫 실행·기존 설정 재사용·설정 변경·교체 거부·취소·오류 복귀·입력 검증 등 10개 추가, **총 87개 자동 테스트 통과**.
- MSYS2 Python에서 실제 Tk 시작 창 생성과 최종 660×491 배치 범위 검사를 통과했습니다. Linux 플랫폼 분기를 모의 실행한 전체 87개도 통과했습니다. Computer Use 도구가 생성된 Python 창을 대상으로 반환하지 않아 스크린샷·버튼 시각 검증은 수행하지 못했습니다.
- 새 GUI에서 실제 캘리브레이션→YOLO→복귀 전체 동작, 일반 Windows CPython 및 Pi GUI는 확인 대기입니다. Pi에는 `python3-tk`와 로컬 데스크톱이 필요합니다.

## 뒷모습·상반신 구도 대응

- 사용자 촬영 조건은 뒷모습·상반신만 보이고 아래가 잘리는 구도입니다. 기존 하단 중심점이 좌석 ROI 밖 또는 프레임 최하단에 있으면 person 상자가 있어도 사람 신호가 사라지는 문제를 회귀 테스트로 재현했습니다.
- 사람은 `overlapping_seat_ratios()`에서 ROI 다각형과 보이는 bbox의 교차 면적을 계산합니다. 정확히 한 좌석과 면적이 겹치고 상자 면적의 50% 이상이면 연결합니다. 하단 중심점이나 보이는 발을 요구하지 않습니다.
- 작은 겹침·여러 좌석 겹침은 관련 좌석을 보류하여 물품만으로 AWAY를 확정하지 않습니다. 다른 좌석과 경계만 접촉하고 면적이 0이면 중복 후보로 보지 않습니다. 기존 확정 상태는 원래 만료 정책을 따릅니다.
- 물품 하단 중심점, YOLO 클래스·confidence, 시간 기반 상태 전이, EMPTY 검증 정책과 좌표 JSON 형식은 유지합니다. 추가 의존성 없이 오목한 다각형도 계산합니다.
- 시작 창·캘리브레이션 화면·README에 책상뿐 아니라 앉은 머리/어깨/등의 화면 영역을 포함하도록 안내했습니다.
- 잘린 상반신→OCCUPIED, 정확한 50% 경계, 좌우 프레임 끝, 약한 겹침, 인접 좌석, 오목/삼각/분리된 교차 영역, 방향·부동소수 좌표·잘못된 bbox를 검증하는 9개 추가로 총 **96개 테스트 통과**. 안내를 추가한 Tk 창의 660×506 배치 범위 검사도 통과했습니다.
- 이 변경은 탐지된 person의 좌석 연결 보완입니다. YOLO가 뒷모습·상반신 자체를 검출하는 정확도는 실제 영상에서 확인해야 합니다. 다중 좌석과 조금이라도 면적이 겹치면 보류하는 초기 정책은 실제 강의실에서 UNKNOWN 비율·통로 보행자 오인식과 함께 보정해야 합니다.

## 다음 작업과 미검증 사항

- `main.py`에서 기존 좌석으로 시작, 좌석 다시 지정, 취소, 결과 화면 종료 후 복귀를 확인합니다.
- 저장한 JSON의 해상도·좌석 위치와 실제 탐지·상태 전이를 현장에서 보정합니다.
- 상반신 촬영에서 person 상자 생성과 confidence를 먼저 확인하고, 해당 상자의 절반 이상이 한 좌석 안에 들어오도록 좌석 영역을 조정합니다.
- bbox가 프레임 최하단에 닿는 사례, 통로 보행자, 인접 좌석 경계 등은 실제 영상에서 확인해야 합니다.
- 현재 `empty_verified`는 테스트 신호입니다. 실제 검증기가 없으므로 빈자리 안내 품질은 아직 검증하지 않았습니다.
- 노트북 YOLO는 사용자 실행 보고를 받았으나 VLM 호환성·인식 정확도, Pi 성능, 스왑·네트워크 검증은 수행하지 않았습니다.
- 이번 GUI 변경은 커밋·푸시하지 않았습니다.
