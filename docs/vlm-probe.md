# 5단계: 로컬 VLM 단독 진단과 현장 평가

2026-11-19 기준. 이 도구는 **모델 실행 가능성·응답 형식·지연·메모리**를 확인합니다.
`main.py`/YOLO 상태 머신과 연결하지 않으며, 백엔드 설정이나 비밀키를 읽지 않습니다.
진단 라벨은 `empty_verified`가 아니며, 현재 운영 실행기는 여전히 `EMPTY`를 확정하지 않습니다.

## 준비와 실행

Pi의 기존 CPU PyTorch·apt OpenCV 환경을 그대로 사용합니다.
이 Pi에는 아래 패키지와 모델 준비를 마쳤습니다. 다른 장치에서만 다시 설치·다운로드하세요.

```bash
.venv/bin/python -m pip install -r requirements-vlm.txt
.venv/bin/python prepare_vlm.py
```

준비 단계만 공식 Hugging Face 모델 저장소에 접속합니다. 고정 리비전
`9cda5c165b28c68a52e9bb542d2b89f0f6963709`의 설정·토크나이저·`model.safetensors`만 받습니다.
ONNX·다른 가중치·원격 Python 코드는 받지 않습니다. 모델 파일은 약 1.03GB이며 Git 제외 경로 `local/`에 둡니다.
런타임은 `local_files_only=True`, `trust_remote_code=False`, safetensors와 오프라인·텔레메트리 차단 설정을 사용합니다.

카메라 없는 검은 RAM 이미지 검사입니다. 기본 가시성 검사가 모델 호출 전에 보류하므로,
이 명령의 지연을 모델 추론 속도로 해석하지 않습니다.

```bash
.venv/bin/python probe_vlm.py --synthetic
```

모델 자체의 오답과 속도를 비교할 때만 가시성 보류를 우회합니다. 아래 모드는 진단 전용이며 운영 검증이 아닙니다.

```bash
.venv/bin/python probe_vlm.py --synthetic --raw-model --compare --samples 1
```

실제 카메라는 Linux에서만 개인정보 보호 사전 검사를 제공합니다. 프로세스 덤프를 차단하고,
스왑이 켜져 있으면 카메라를 열기 전에 실패합니다. 이 Pi의 스왑은 systemd가 관리하는
zram이며 디스크 backing도 있으므로, 테스트 동안만 중지하고 **프로세스 종료 후** 원복합니다.
아래는 현재 Pi에 확인된 명령입니다. 다른 장치는 `/proc/swaps`와 관리 방식을 먼저 확인하세요.

```bash
# main.py의 탐지를 먼저 종료하세요. 아래는 실제 빈자리로 준비한 A-01의 예입니다.
(
  set -e
  sudo systemctl stop dev-zram0.swap
  trap 'sudo systemctl start dev-zram0.swap' EXIT
  .venv/bin/python probe_vlm.py --seat A-01 --expected EMPTY
)
```

`--expected`는 테스트 당시 사람이 확인한 정답입니다. 착석은 `OCCUPIED`, 사람 없이 짐만 있으면
`AWAY`, 가려지거나 좌석이 안 보이면 `UNKNOWN`으로 바꾸세요. 장면을 유지한 채 실행합니다.
정답이 없으면 이 옵션을 생략할 수 있지만, 그 결과로 정확도를 계산할 수 없습니다.
`--config`와 `--camera`로 기존 좌표·카메라를 선택합니다. 해상도가 달라지면 거부하며 자동 좌표 보정은 없습니다.

현재 진단 기본값은 영어 선택형 질문(`choices`), CPU float32/SDPA, 스레드 2개, 이미지 최장변 256,
이미지 분할 없음, 최대 생성 8토큰, 샘플 3개, 가시성 보류 활성화입니다.
기존 긴 상태 질문은 `--profile labels --image-edge 512`로 재현합니다. `--language ko`는 한국어 비교용입니다.
256 입력에서는 비전 입력 크기와 `image_seq_len=16`을 함께 설정하며, 512에서는 64로 복원합니다.
작은 입력이 휴대전화·필통 같은 물품에 미치는 정확도 영향은 아직 검증하지 않았습니다.

## SSH에서 네 상태를 직접 비교

실제 정답은 사람이 준비하고 확인해야 합니다. 에이전트가 정답을 추측하거나 합성 이미지로 현장 정확도를 대신 측정하지 않습니다.
먼저 A-01 다각형에 실제 책상·의자와 착석한 사람의 머리·어깨·등이 들어오도록 기존 캘리브레이션을 확인합니다.
이미지 저장 없이, 터미널 안내에 따라 **착석 → 짐만 있음 → 빈자리 → 가림**을 순서대로 준비한 뒤 Enter를 누릅니다.
촬영과 네 조합 비교가 끝나 다음 안내가 나올 때까지 장면을 유지하세요. `s`는 해당 상태 건너뛰기, `q`는 종료입니다.

```bash
(
  set -e
  sudo systemctl stop dev-zram0.swap
  trap 'sudo systemctl start dev-zram0.swap' EXIT
  .venv/bin/python probe_vlm.py --seat A-01 --interactive --compare --samples 1 --report local/vlm-manual-evaluation.json
)
```

`--compare`는 매 촬영의 **동일한 RAM 프레임**에 긴 질문/선택형 × 512/256의 네 조합을 적용합니다.
한 번에 한 조합만 계산하고, 다음 조합을 위해 이미지를 작업 프로세스 안에서만 유지한 뒤 마지막 계산 후 해제합니다.
한 촬영의 전체 비교는 최대 네 조합 × 15초로 제한되며, 조합 하나가 시간 초과하면 전체 작업자를 종료합니다.
따라서 뒤쪽 조합의 `observation_age_seconds`는 누적됩니다. 이 라벨들은 과거 프레임의 진단이며 현재 상태에 적용하지 않습니다.

정답 라벨은 부모 프로세스에서만 결과와 대조합니다. 모델 입력/작업자 설정으로 전달하지 않습니다.
`--cases OCCUPIED AWAY`처럼 준비 가능한 상태만 지정할 수 있지만, 빠진 상태가 있으면 전체 검증 완료로 표시하지 않습니다.
반복 측정은 `--samples 3` 등으로 늘립니다. 한 장·한 회씩으로 현장 정확도나 P95를 확정할 수는 없습니다.

결과 파일은 메타데이터 JSON만 담으며 기존 파일은 덮어쓰지 않습니다. 재실행 시 새 이름을 사용하세요.
중간에 종료하거나 시간 초과해도 수집한 결과와 그 상태를 보존합니다. `local/`은 Git 제외 경로입니다.
프로세스가 종료된 뒤 스왑을 원복하며, 이미 돌아가는 `main.py`의 탐지는 시작 전에 종료하세요.

## 판정과 중단

- 준비된 모델을 별도 프로세스 하나에 먼저 로드한 뒤 카메라를 엽니다. 한 번에 작업 하나만 실행하며 대기 이미지 큐가 없습니다.
- 좌석 다각형의 bounding rectangle만 RAM에 복사하고, 다각형 밖은 회색으로 가립니다. 인접 좌석 화면을 그대로 포함하지 않습니다.
- 이미지 경로·URL을 모델에 전달하지 않고 RAM의 PIL RGB 이미지로 직접 처리합니다. 촬영 뒤 카메라를 닫고, 요청 완료 시 PIL·프레임·입력 텐서 참조를 해제합니다.
- 기존 질문은 네 상태 라벨 중 하나만 받습니다. 선택형은 `A=OCCUPIED`, `B=AWAY`, `C=EMPTY`, `D=UNKNOWN`으로 변환하며 단일 문자 뒤 마침표 하나만 허용합니다. 어느 방식이든 EOS로 끝나야 하고, 설명 문장·여러 답·잘린 응답은 UNKNOWN입니다. 생성 점수를 확률로 사용하지 않습니다.
- 기본 가시성 검사는 ROI 안 픽셀만 사용합니다. 최소 크기 32픽셀·1024픽셀 면적 미달, 평균 밝기 12 미만/243 초과, 밝기 5~95백분위 범위 16 미만이면 UNKNOWN으로만 보류합니다. 회색 마스크로 통계를 보완하지 않습니다. 개발용 초기 임계값이며 일반적인 가림·흐림 판별기나 빈자리 검증기는 아닙니다.
- `format_valid`로 모델의 형식 준수를 구분합니다. 형식 오류로 보류한 UNKNOWN은 `--expected UNKNOWN`이어도 모델 정답으로 집계하지 않아 `matches_expected=false`입니다. 모델을 호출하지 않은 가시성 보류는 `model_ran=false`, `format_valid=null`, `matches_expected=null`입니다. 최종 보류 결과의 정답 여부는 별도 `system_matches_expected`입니다.
- 기본 제한은 첫 조합의 촬영·전처리·추론, 이후 각 조합의 추론에 15초씩입니다. 초과 시 자식 프로세스를 종료·회수한 뒤 `UNKNOWN/VLM_TIMEOUT`을 출력하고 코드 2로 끝납니다. 모델 초기 로드 제한은 별도 60초입니다. 정상 종료 코드 0은 측정을 끝냈다는 뜻이며 정확도 합격을 의미하지 않습니다.
- Linux 작업자는 부모 프로세스가 사라질 때도 종료되도록 설정합니다. 스왑 조건은 초기 로드 전과 매 촬영 직전에 확인합니다.
- 표준 출력/프로세스 통신에는 라벨·소요 시간·토큰 수·RSS 등 메타데이터만 담습니다. 생성 문장·프레임·crop·배열·이미지 파일·네트워크 전송은 구현하지 않습니다.
- `captured_at`은 카메라 읽기 직후의 monotonic 시각, `frame_id`는 이번 실행의 촬영 번호입니다. `observation_age_seconds`는 이후의 누적 경과 시간입니다. 오래된 라벨을 최신 관측으로 바꾸거나 상태에 적용하지 않습니다. 향후 통합 시 캡처 시각·frame ID·generation 검증이 별도로 필요합니다.

## 후속 비교 결과와 집계 기준

2026-11-19 같은 프레임에서 네 조합을 순차 비교했습니다. 아래 수치는 각 한 회의 추론 시간입니다.

| 질문·입력 | 검은 합성 입력, 가시성 보류 우회 | 실제 C270 A-01, 가시성 검사 활성화·strace 사용 |
| :--- | :--- | :--- |
| 긴 질문·512 | 6.693초, 형식 오류 → UNKNOWN | 7.625초, 형식 오류 → UNKNOWN |
| 선택형·512 | 5.216초, AWAY 오답 | 5.938초, EMPTY, 형식 준수 |
| 긴 질문·256 | 3.250초, 형식 오류 → UNKNOWN | 6.139초, 형식 오류 → UNKNOWN |
| 선택형·256 | 2.027초, EMPTY 오답 | 2.915초, EMPTY, 형식 준수 |

선택형은 이번 비교에서 형식을 지켰지만, 검은 입력을 정확히 판단하지 못했습니다.
가시성 보류를 켠 검은 입력은 네 조합 모두 모델 호출 없이 UNKNOWN으로 보류했습니다.
실제 카메라 장면은 아직 사람이 확인한 정답이 없어 `model_accuracy=null`입니다.
실제 비교 작업자 peak RSS는 1566MiB였고, 네 조합이 같은 모델 프로세스를 공유한 값입니다.
이 결과는 **형식·속도 개선** 근거이며, 실제 네 상태의 정확도나 작은 물품 검출률을 검증한 결과는 아닙니다.
영어 선택형을 비교했고, 한국어 질문의 현장 품질은 아직 측정하지 않았습니다.

실제 카메라의 후속 파일·네트워크 추적에서도 외부 connect/send와 이미지 파일 열기를 관찰하지 않았습니다.
새로 저장한 파일은 명시적으로 요청한 메타데이터 JSON이며 이미지·생성 문장은 포함하지 않습니다.
정상 종료 후 zram 스왑을 원복했습니다. 후속 전체 자동 테스트는 **162개(기존 136 + VLM 26)** 통과입니다.

보고서 `summary.by_variant`는 조합별로 다음을 분리합니다.

- `coverage`, `all_states_sampled`: 사람이 확인한 정답 또는 알려진 합성 대조군의 상태별 표본 수. 정답 없는 영상은 제외하며, 한 상태만으로 네 상태를 검증했다고 표시하지 않습니다.
- `format_compliance`: 모델을 실제 호출한 결과 중 형식 준수 비율. 가시성 보류와 시간 초과를 형식 성공으로 집계하지 않습니다.
- `model_accuracy`: 정답 있는 실제 모델 호출 중 **유효 형식의 정확한 라벨** 비율. 형식 오류의 UNKNOWN을 모델 정답으로 집계하지 않습니다. 분모가 없으면 null입니다.
- `system_correct`, `guard_abstentions`, `unknown_count`, `timeouts`: 최종 보류 결과의 정답 수와 보류·확인 불가·시간 초과 횟수입니다. 모델 정답 수와 구분합니다.
- `false_empty_count/rate`: 정답이 OCCUPIED 또는 AWAY인 표본에서 EMPTY로 잘못 답한 수/비율입니다. 점유 정답 표본이 없으면 비율은 null이며 0% 성공으로 간주하지 않습니다. 정답 UNKNOWN을 EMPTY로 답한 경우는 `unknown_as_empty_count`로 별도 기록합니다.
- `confusion_matrix`: 정답 행 × 최종 라벨 열. 정답 없는 관측은 제외합니다. `runtime_enabled`는 항상 false이며 보고서 결과가 운영 기능을 자동 활성화하지 않습니다.

현재는 네 상태의 현장 정답 표본을 모으는 단계입니다. 품질을 통과한 뒤에만 YOLO와 별도 워커로 연결하고
frame ID·generation·캡처 시각·지속 부재를 함께 검증합니다. 가시성 검사 통과나 모델의 EMPTY 응답 하나만으로
`empty_verified`를 만들지 않습니다.

모델의 공식 설명은 [SmolVLM2-256M 모델 카드](https://huggingface.co/HuggingFaceTB/SmolVLM2-256M-Video-Instruct),
사용법은 [Transformers SmolVLM 문서](https://huggingface.co/docs/transformers/model_doc/smolvlm)를 따릅니다.
공식 예제의 CUDA/FlashAttention 대신 이 장치에서는 CPU float32/SDPA를 실제 실행했습니다.
